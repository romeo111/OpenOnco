Åben kildekode

Deltag i OpenOnco

Hjælp med at verificere koden, bevismateriale og nytte til onkologidiskussion.

Klinisk indhold er foreløbigt og kræver verifikation af en kvalificeret onkolog. Ingeniørtest er ikke klinisk validering. Brug kun syntetiske data i offentlige rapporter.

Til udviklere

  1. Prøv demoen uden tilmelding — vælge et syntetisk eksempel og undersøge dets kildeforbindelser.
  2. Til lokal udvikling: Python 3.12, isoleret miljø og krav.lock.
git clone https://github.com/romeo111/OpenOnco.git
cd OpenOnco
python -m venv .venv
# Activate .venv for your operating system, then:
python -m pip install -r requirements.lock
python -m pip install --no-build-isolation --no-deps -e .
python scripts/audit_validator.py --human
python -m http.server 8000 --directory docs

For kliniske reviewere

Start med DLBCL's førstelinjepakke: Syntetiske scenarier, regelspor og lokal feedback-eksport. Vælg et scenario inden for din ekspertise, sammenlign output med originale kilder og rekord afvigelser.

Åbn anmeldelsespakken · Review report model

Lægediskussion og PDF

I Plan Builder, åbne et syntetisk eksempel eller genereret plan, skal du vælge "Del med din læge · PDF", derefter "Gem som PDF" i browseren. Planen selv er trykt med sin kilde citeringer. Din kliniker skal verificere anvendelighed; ikke ændre behandling selv.

Standarder og integrationer

En indledende mCODE/FHIR R4 felt kortlægning og hulanalyse er tilgængelig. En FHIR/OMOP adapter og demonstreret mCODe overensstemmelse er under afventning.

Analyse af manglende indbyrdes forbindelser · mKODE 4.0.0 · OHDSI Onkologi WG

Forældregrupper og ressource-undersøgte klinikker

Et nyttigt første samarbejde er at gennemgå uddannelsesmæssige formulering og forberedelse af spørgsmål ved hjælp af syntetiske eksempler. Enhver pilot har brug for en ansvarlig klinisk reviewer, lokal kontekst og privatlivslig gennemgang. Gratis kode betyder ikke adgang til lægemidler eller licenserede retningslinjer.
