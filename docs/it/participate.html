Partecipare a OpenOnco

Aiuta a verificare il codice, le tracce di evidenza e l'utilità per la discussione oncologica.

Il contenuto clinico è provvisorio e richiede la verifica da parte di un oncologo qualificato. I test tecnici non sono convalida clinica. Utilizzare i dati sintetici solo nei rapporti pubblici.

Per gli sviluppatori

  1. Prova la demo senza iscrizione — scegliere un esempio sintetico e ispezionare i suoi collegamenti di origine.
  2. Per lo sviluppo locale: Python 3.12, un ambiente isolato e requisiti.lock.
git clone https://github.com/romeo111/OpenOnco.git
cd OpenOnco
python -m venv .venv
# Activate .venv for your operating system, then:
python -m pip install -r requirements.lock
python -m pip install --no-build-isolation --no-deps -e .
python scripts/audit_validator.py --human
python -m http.server 8000 --directory docs

Per i revisori clinici

Inizia con il pacchetto di prima linea DLBCL: scenari sintetici, tracce di regole e esportazione di feedback locali. Scegli uno scenario all'interno della tua competenza, confronta l'output con le fonti originali e registra discrepanze.

Discussione del medico e PDF

In Plan Builder, aprire un esempio sintetico o piano generato, selezionare їCondividere con il medico · PDF ), poi їSalva come PDF . Il piano stesso è stampato con le sue citazioni di sorgente. Il medico deve verificare l'applicabilità; non cambiare il trattamento da solo.

Norme e integrazioni

È disponibile un'analisi iniziale del campo e del gap di mCODE/FHIR R4. Un adattatore FHIR/OMOP e la conformità mCOde dimostrata sono in attesa.

Gruppi di difesa e cliniche con risorse limitate

Una collaborazione iniziale utile è la revisione della formulazione educativa e la preparazione delle domande utilizzando esempi sintetici. Qualsiasi pilota ha bisogno di un revisore clinico responsabile, contesto locale e revisione della privacy. Codice gratuito non implica l'accesso ai farmaci o linee guida con licenza.
