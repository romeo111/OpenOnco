Specifiche

OpenOnco è un progetto di specifiche-primo. Ogni dettaglio architettonico, clinico e di governance è inquadrato in un documento di markdown sotto specs/ that is versioned and open to public review. 10 active specifications cover everything from FDA non-device CDS positioning to the shape of every YAML entity in the KB. The full text lives at github.com/romeo111/OpenOnco/specs.

Gerarchia della fonte della verità (da CLAUDE.md): quando le specifiche sono in conflitto, l'ordine vincolante è 1. CARTA.md → 2. altri specs/*.md → 3. CLAUDE.md → 4. README.MD. Qualsiasi cosa sotto legacy/ Non è autorevole.

Specifiche attive (10)

Governanza CHARTER.md

Carta e governance

Project governance, scope (what it does and what it explicitly does not), FDA non-device CDS positioning (§15 with constraints C1-C7), the solo-maintainer workflow for source-traceable content (§6.1), patient-data privacy (§9.3), forbidden prompt patterns for LLMs (§8.3 — LLMs do not make clinical decisions).

Clinico CLINICAL_CONTENT_STANDARDS.md

Standard di contenuto clinico

Standard di contenuto clinico: formato di citazione (source_id + posizione + parafrase + pagina), taxonomia a livello di evidenza (Tier 1-6), processo di approvazione del revisore, STUB → criteri di transizione rivisti. Ogni richiesta in un Indicazione / Regime / RedFlag collega ad un Ente Sorgente.

Dati DATA_STANDARDS.md

Norme sui dati — Modello del paziente

Patient profile data model. FHIR R4/R5 + mCODE alignment on the roadmap. Code systems: LOINC + ICD-10/O-3 + RxNorm + CTCAE v5.0. No SNOMED CT and no MedDRA in the MVP (license gates). Profile fields and semantic interoperability.

Pydantic schemas for every KB entity — Disease / Indication / Regimen / Algorithm / Biomarker / Drug / Test / Workup / RedFlag / Contraindication / MonitoringSchedule / SupportiveCare / Source. Defines fields, validators, referential-integrity rules, and the migration roadmap to PostgreSQL.

Guida software di supporto alla decisione clinica della FDA

The official FDA guidance on non-device CDS classification under §520(o)(1)(E). Hosted under specs/ as a PDF. CHARTER §15 cites concrete criteria 1-4 from this document to justify OpenOnco's non-device positioning.

Come aggiornamo le specifiche

Progetto singolo. Un manutentore fornisce aggiornamenti con controlli automatizzati e tracciabilità delle sorgenti. La revisione clinica esterna è opzionale e viene registrata separatamente.

Tutte le specifiche sono scritte Ucraino-Primo (l'interfaccia e i revisori clinici sono UA), ma termini tecnici e nomi di licenza rimanere in inglese inline. La versione è via git: ogni spec porta v0.1 (draft) nella testata e viene sbattuto su minore/maggiore a seconda delle modifiche di rottura.
