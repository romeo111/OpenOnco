## 1. The goal (user's words, paraphrased)

Make OpenOnco **searchable in "LLM info"** so:
1. When a doctor does oncology research inside a regular LLM (ChatGPT, Claude,
   Perplexity, etc.), the LLM **routes through OpenOnco's deterministic engine**
   for safer, source-cited results instead of hallucinating regimens/doses.
2. Other builders can **find and replicate** the project (full open source).
3. Ultimately, every doctor in the world can use the app.

This is a **GEO/discoverability + integration** task, not a clinical-content
task. The hard part — a callable engine + the discovery metadata — is done; what
remains is **publishing, registering, and OpenAI-ecosystem integration.**

  the engine's cited output, never substitute its own regimen (CHARTER §8.3).

`mcp_server/http_server.py` (FastMCP streamable-HTTP) importing the **same**
`engine_bridge` functions — no engine logic duplicated. Hosting it raises a
CHARTER §9.3 question only if patient data hits the server; keep it stateless
and tell users not to send identifiable data (the README already says this).

## 6. File / architecture map

- Engine entry points (deterministic, the decision-maker): `generate_plan`,
  `generate_diagnostic_brief`, `orchestrate_mdt`, `revise_plan` — exported from
  `knowledge_base/engine/__init__.py`. CLI: `python -m knowledge_base.engine.cli`.
- MCP bridge: `mcp_server/engine_bridge.py` (no `mcp` dep) → `mcp_server/server.py`.
- Discovery generation: `scripts/site_head.py`
  (`finalize_site_discovery` writes sitemap/robots/llms/llms-full + injects
  per-page JSON-LD via `inject_seo_metadata`). Called from
  `scripts/build_site.py::build_site` at the end.
- Site build: `scripts/build_site.py` (**hook-guarded** — staging it requires
  staging a `docs/` rebuild; avoid editing it for discovery tweaks).
- KB content: `knowledge_base/hosted/content/<entity>/*.yaml`.
- Schemas: `knowledge_base/schemas/` (Pydantic).
- Validator: `python scripts/audit_validator.py --human`.
