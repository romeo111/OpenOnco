Especificações

OpenOnco é um projeto de especificações-primeiro. Cada detalhe arquitetônico, clínico e de governança é preso em um documento de marcação abaixo specs/ that is versioned and open to public review. 10 active specifications cover everything from FDA non-device CDS positioning to the shape of every YAML entity in the KB. The full text lives at github.com/romeo111/OpenOnco/specs.

Gerarquia da fonte da verdade (de CLAUDE.md): quando especifica em conflito, a ordem vinculativa é 1. CARTA.md → 2. Outros specs/*.md → 3. CLAUDE.md → 4. README.MD. Qualquer coisa abaixo legacy/ Não é autoritário.

Especificações ativas (10)

Governação CHARTER.md

Carta e Governação

Project governance, scope (what it does and what it explicitly does not), FDA non-device CDS positioning (§15 with constraints C1-C7), the solo-maintainer workflow for source-traceable content (§6.1), patient-data privacy (§9.3), forbidden prompt patterns for LLMs (§8.3 — LLMs do not make clinical decisions).

Dados DATA_STANDARDS.md

Padrões de dados — Modelo de paciente

Patient profile data model. FHIR R4/R5 + mCODE alignment on the roadmap. Code systems: LOINC + ICD-10/O-3 + RxNorm + CTCAE v5.0. No SNOMED CT and no MedDRA in the MVP (license gates). Profile fields and semantic interoperability.

Pydantic schemas for every KB entity — Disease / Indication / Regimen / Algorithm / Biomarker / Drug / Test / Workup / RedFlag / Contraindication / MonitoringSchedule / SupportiveCare / Source. Defines fields, validators, referential-integrity rules, and the migration roadmap to PostgreSQL.

Fonte regulamentar (PDF)

PDF regulamentar Guidance-Clinical-Decision-Software_5.pdf

FDA Orientação de Software de Suporte à Decisão Clínica

The official FDA guidance on non-device CDS classification under §520(o)(1)(E). Hosted under specs/ as a PDF. CHARTER §15 cites concrete criteria 1-4 from this document to justify OpenOnco's non-device positioning.

Como atualizamos as especificações

Projeto individual. Uma pessoa responsável publica as atualizações com verificações automáticas e rastreabilidade das fontes. A revisão clínica externa é opcional e registada separadamente.

Todas as especificações são escritas ucraniano-primeiro (a interface e os revisores clínicos são UA), mas termos técnicos e nomes de licença permanecem em inglês inline. v0.1 (draft) no cabeçalho e é chocado em menor/maio, dependendo de quebras de mudanças.
