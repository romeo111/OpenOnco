Öppen källkod

Specifikationer

OpenOnco är ett första projekt med specifikationer. Varje detalj om arkitektur, klinisk och styrning finns i ett dokument under specs/ that is versioned and open to public review. 10 active specifications cover everything from intended-use design constraints to the shape of every YAML entity in the KB. The full text lives at gethub.com/romeo111/OpenOnco/specs.

Sannhetshierarki (från CLAUDE.md): När specs konflikter, bindande order är 1. CHARTER.md → 2. andra specs/*.md → 3. KLAUDE.md → 4. README.md. Allt under legacy/ inte är auktoriserat.

Aktiva specifikationer (10)

Styrelseformer CHARTER.md

Stadga och styrelseformer

Project governance, scope (what it does and what it explicitly does not), intended-use design constraints (§15 with constraints C1-C7), the solo-maintainer workflow for source-traceable content (§6.1), patient-data privacy (§9.3), forbidden prompt patterns for LLMs (§8.3 — LLMs do not make clinical decisions).

Kliniskt CLINICAL_CONTENT_STANDARDS.md

Standarder för kliniskt innehåll

Standarder för kliniskt innehåll: citeringsformat (source_id + position + parafras + sida), evidens-nivå taksonomi (TIER 1-6), verifierings-avslöjningsarbetsflöde, STUB → reviderade övergångskriterier. Varje krav i en indikation / Regimen / RedFlag länkar till en källenhet.

Läs på GitHub → Råmarkering
Uppgifter DATA_STANDARDS.md

Datastandarder – patientmodell

Patient profile data model. FHIR R4/R5 + mCODE alignment on the roadmap. Code systems: LOINC + ICD-10/O-3 + RxNorm + CTCAE v5.0. No SNOMED CT and no MedDRA in the MVP (license gates). Profile fields and semantic interoperability.

Schema KNOWLEDGE_SCHEMA_SPECIFICATION.md

Specifikation av kunskapsschemat

Pydantic schemas for every KB entity — Disease / Indication / Regimen / Algorithm / Biomarker / Drug / Test / Workup / RedFlag / Contraindication / MonitoringSchedule / SupportiveCare / Source. Defines fields, validators, referential-integrity rules, and the migration roadmap to PostgreSQL.

Källor SOURCE_INGESTION_SPEC.md

Källintag och licensiering

Hur vi intar källor: värdmatrisen (referens kontra värd kontra blandad) med H1-H5-begrundning, licensklassningsportar, checklistan för tilläggs-a-källa (§8), checklista för värd-källan (§20) och SourceClientprotokollet för levande API.

Testning REFERENCE_CASE_SPECIFICATION.md

Referensfall – "Patient Zero"

Ett syntetiskt HCV-MZL-referensfall som P0-acceptanstest. Definierar alla erforderliga patientprofilfält (§2-mallar), de kritiska strukturella påståendena för Plan reproducering (§1.3) och milstolpar M1-M6 för expanderande täckning.

Motor MDT_ORCHESTRATOR_SPEC.md

MDT Orkester + beslutsprovenu

Orchestrate_mdt rules (R1-R9 for treatment, D1-D6 for diagnostic), role activation logic (required / recommended / optional), the Open Questions mechanism (Q1-Q6 + DQ1-DQ4 — the engine refuses to decide without the required data), and a decision-provenance graph for audit-grade explanation.

Motor DIAGNOSTIC_MDT_SPEC.md

Diagnostisk-fas MDT (prebiopsi)

Pre-biopsy mode: when histology is not yet available the engine emits a DiagnosticPlan with a workup brief instead of a treatment Plan. CHARTER §15.2 C7 hard rule. DiagnosticWorkup + DiagnosticPlan schemas, generate_diagnostic_brief(), polymorphic orchestrate_mdt with DQ1-DQ4 rules.

Arbetssätt Forskningsmetodik

Hur vi bygger upp en grundläggande arbetsplats för alla onkologiska områden. Källhierarki (Tier 1: NCCN/ESMO/EHA/BSH/WHO/ASH), Test/Arbetsfullständighet checklistor, 7-stegsprocessen för att utöka täckning till en ny domän, anti-mönster.

Skill-orienterad arkitektur (MDT Roller som färdigheter)

Formalises MDT roles (haematologist / pathologist / radiologist / etc.) as clinically-verified skills — each skill carries version, sources, last_reviewed, clinical_lead. Sizing horizon (~12-15 MVP → 50-60 comprehensive), 8-domain layout, 5-phase refactor plan.

Hur vi uppdaterar specifikationerna

Solo-projektet. En underhållare levererar uppdateringar med automatiska kontroller och källspårbarhet. Extern klinisk granskning är valfri och registreras separat.

Alla specifikationer är skrivna ukrainska-först (gränssnittet och de kliniska granskarna är UA), men tekniska villkor och licensnamn stanna på engelska inline. Versioning är via git: varje spec bär v0.1 (draft) i rubriken och stötas på mindre/stor beroende på att förändringarna bryts.
